# A股桌面盯盘挂件

> 半透明、置顶、可拖动的 Windows 11 桌面小挂件。最多盯 5 只 A 股，实时刷新，带分时走势缩略图，顶部常驻大盘指数，涨跌超阈值自动提醒。

当前版本：**v2.1.4** · 更新于 2026-09-20 · [下载](https://github.com/Fallenathenaaa/astock-widget/releases/tag/v2.1.4)

## 版本特点

### v2.1.4（当前）

**压力路径下的两个竞态 + 数据语义收尾**

- 🔀 **切源 / 换自选后不会再出现"分时图空白"**：上一版把"旧源数据污染新缓存"堵住了，但留下一个全局计数 —— 旧一代的填充流程结束时会把它重新抬高，于是新身份那一轮读到"计数 > 0"就直接返回，不发请求。价格已经是新源的，分时却空白着要等计数归零（交易时段最长接近 5 分钟）。这个计数和每条缓存自己的过期时间是重复的第二套状态，已删掉
- 🏷 **价格读不出来不再被当成"停牌"**：接口偶尔给 `--` 这种占位符，以前 `price` 会变成 0，接着被判成停牌。现在这种**整条行情作废**，改由备源补缺；两个源都坏时这一行就是缺失，而不是挂一个假的停牌标记
- 📉 **负成交量也不算"零成交"**：成交量不可能为负，出现就是坏数据，按"没给"处理
- 🔒 **建完 tag 后的验证改成 fail-closed**：以前只在"读到了错误的 commit"时拦；**完全读不到**（重试后仍 404、或服务器错误）反而放行 —— 等于验证了个寂寞。现在查不清就停
- 🧪 **"没碰你的真实数据"现在按内容证明**：以前只比文件名，某个既有备份被覆盖写、日志被追加都看不出来。现在采样每个文件的 (大小, SHA-256)
- 🐍 **Python 版本表真正收敛到一处**：`install.bat` 以前自己抄了一份 `3.14 3.13 ...`，helper 改了它还在原地。现在安装脚本用 `check_python.py --find` 问，并且加了测试防止以后又复制回去

### v2.1.3

**异步缓存身份 + 数据置信度 + 发布事务一致性**

- 🔀 **切数据源后旧源的分时不再残留**：分时缓存条目现在带着自己的 (源, generation)。以前旧请求在途时切源，切源虽然清了缓存，但**旧请求回来会把它那份再写一遍** —— 价格是新源的，迷你分时却是旧源画的，最长能吃满整个缓存期。现在旧身份的条目既写不进来也命中不了
- 💰 **超大整数持仓不再清空整份配置**：JSON 里一个 400 位的数字会让 `float()` 抛 `OverflowError`，之前的结果是**整份 `positions` 回退成空**，连合法的那几条一起丢。现在只丢坏的那一条
- 📉 **畸形成交量也不当 0**：接口偶尔给 `--` 这种占位符，之前会被当成成交量 0 → 误判停牌。现在"读不出来"和"成交量是 0"分开处理，只有明确给了 0 才判停牌
- 🏷 **推算的涨跌停价不再产生涨跌停徽标**：新浪不给涨跌停价，只能按板块规则算。那个近似值以前会驱动一个看起来确定的「涨停」徽标，而界面上没有任何地方显示"这是估的"。**不确定就少说** —— 推算值仍留在数据里做参考，但不再产生权威判定；腾讯给的仍照常判
- 🔒 **发版前最后再核一次 main**：打 tag 之前会重新读远端 main，变了就停 —— 避免打出"main 是 B、tag 打在 A"这种 Release 和 main 不一致的情况
- 🐍 **升级用户的旧 `.venv` 也要过版本闸**：以前只在**新建** venv 时挑 Python，老用户已有的 3.8 / 3.9 venv 会被原样复用，README 上写的 3.10–3.14 成了空话。现在 `install.bat` / `start.bat` 每次都验，不合格会明确报出来并停住（不会偷偷替你删）
- ♾️ **来自网络的数字一律 finite-aware**：接口给 `1e999` 或 400 位数字时，不再让 `inf` 流进价格 / 涨跌幅 / 涨跌停比较
- 🧪 **测试总数环境无关**：本机和干净 checkout 现在都是同一个数字（以前差 5 —— 真实 `stocks.json` 存在时才多算那几项）。"测试没碰你的真实数据"也从"拍完照片和自己比"改成**开始前采样、结束后比对**
- 📝 **`title: null` 不再变成字面量 `None`**；README 收盘彩蛋的触发描述改成真实的 14:57–15:00 窗口语义

### v2.1.2

**边界正确性 + Provider 语义 + 发版工具事务性**

- 🎯 **优先源不再被"没功劳"的备源抢走**：主源回来一半、备源补上剩下的，以前备源会把下一轮的优先源抢走 —— 明明主源好用，下一轮却先去问更慢的备源。现在 `last_ok` 只认**本轮第一个真正给出数据的源**
- 📉 **成交量「没给」≠「给了 0」**：接口响应被截断时成交量那一列根本不存在，以前按 0 处理，被判成停牌 —— 一只正常交易的股票价格显示成 `--`、涨跌额和盈亏一起被藏掉。现在缺列就是 `None`，只有明确给了 0 才判停牌
- ♾️ **配置挡住 ±inf**：JSON 允许写 `1e999`，解析出来是 `inf`，而 `int(inf)` 抛的是 `OverflowError` —— 以前不在兜底范围里，一个字段坏就把**整份配置**推翻回默认。现在先判有限，坏一个字段只回退那一个
- 🧾 **手填持仓也要过校验**：`600519=nan` / `600519=-10` / `600519=1000:-100` 以前能直接进运行时配置，只有重启读盘时才被清掉。现在输入那一步就走同一套 sanitizer
- 🏷 **tag 名只能来自 APP_VERSION**：以前 `release_tag.py v9.9.9` 能发一个和代码版本完全对不上的 tag。现在不接受命令行指定，版本号只有一个真相源
- 🧯 **发版能续上、不会卡死**：建 tag 成功、建 Release 失败会留下孤儿 tag，以前只会报「tag 已存在」然后退出 —— 那个版本就再也发不出去。现在先查状态：孤儿就只补建 Release，tag 指向别的 commit 一律拒绝
- 🚦 **发版前强制跑检查**：`release_tag.py` 建任何东西之前先跑 `release_check.py`，并查这个 commit 的 Actions 结论；红了直接拒绝发版
- 🔎 **自选代码必须认得出来**：配置里的 `codes` 以前只验"是字符串"，`60051` / `hk00700` / `sh900901` 都能躺进去，取不到行情就是一行永远空白的格子。现在逐条过 `normalize_code()`
- 🔤 **`data_source` / `boss_key` 白名单**：拼错的源名会被静默忽略（表现是"我明明手选了腾讯怎么还在用新浪"）；认不出来的老板键根本注册不了。现在都回退到可用值
- 💾 **写盘失败不再静默**：磁盘满 / 文件被占用时以前是 `except: pass`，改了一堆设置退出后全没了且没有任何提示。现在会弹一条通知，并记下失败原因
- 🏷 **每条行情带来源标记**：一屏里可能混着两个源的数据（主源漏一只、备源补上），`provider` 记这行是谁给的；界面上**只有这行不是期望那个源给的**时候，才在代码后面跟一个灰色小字（"新浪"/"腾讯"）。99% 的时间它不显示，满屏都是同一个源名是噪音不是信息；它出现的时刻就是"主源这次没给全"的信号。`limit_estimated` 标出涨跌停价是接口给的还是按板块推算的（UI 不展示 —— 涨跌停价本身就没画在界面上）
- 🗓 **休市表有"覆盖年限"了**：`calendar_is_maintained(year)` / `calendar_horizon()`，进入 11 月还没补上明年的表，测试会自己变红，不用谁记得
- 🐍 **`install.bat` 先挑受支持的 Python**：以前拿系统默认的就建 venv，3.9 / 3.15 会"建成功"然后在 pip 里报个跟真正原因无关的错。现在先按 3.14→3.10 试，找不到就明确说"需要 3.10–3.14"
- 🔁 **`start.bat` 缺依赖就交回 `install.bat`**：以前只试一个镜像源，那个源挂了就报"程序坏了"
- ⌨️ **老板键 `MOD_NOREPEAT`**：按住不放时系统只发一次，不再按键盘重复率把窗口抽成 hide/show/hide/show
- 📝 **文档对齐**：README 里"同一只 5 分钟内不重复"改成实际的边沿触发语义；`search_stocks()` 的注释以前和 fallback 行为写反了

### v2.1.1

**按第三方复核逐条修：数据正确性 + 并发收敛 + 配置兜底**

- 📅 **2026 休市日补齐**：照上交所公告（上证公告〔2025〕45 号）补到 **19 天**，之前漏了 9 个工作日（元旦次日、春节整周、清明、五一、端午），那些日子会被当成正常交易日
- 🏷 **指数名字不再按下标取**：`sh000001` 和 `sz000001` 的后六位都是 `000001`，以前"第 0 个叫上证"，接口漏返回一只或乱序就会把深证的涨幅挂到上证那格。现在名字跟完整代码绑死，漏了就空一格（`上证 --`），绝不串位
- 🔀 **三个入口各记各的源**：搜索降级到新浪，以前会顺手把下一轮**行情**的数据源优先级也带偏。现在 quotes / search / spark 各用一条链
- 🧩 **主源只回一半时备源补缺**：请求 A/B/C、腾讯只回 A/C 时，以前 B 直接从界面消失。现在只把缺的那只拿去问新浪，最后按原请求顺序合并
- 🔄 **切数据源会让在途结果作废**：换源跟换自选一样 generation +1，旧源的请求回来了也不进界面
- 🔒 **worker 状态一律走 setter**：GUI 线程以前直接改 `fetcher.fast` / `show_index` / `source`，绕过了锁。现在统一 setter，锁里改
- ⏳ **退出等待按源数量算**：单源超时 5 秒、自动降级最坏 10 秒，原来固定等 6.5 秒已经盖不住。现在按「源数 × 超时 + 余量」算，并且每次网络调用后都看一眼退出标志
- 🛡 **截断响应不再崩**：解析里写的是 `len(f) < 35` 紧接着又取 `f[36]`，长度正好 35/36 时 `IndexError`，整只股票消失。改走安全取值，并补了各边界长度的用例
- ✅ **布尔值按字面算**：配置里写 `"click_through": "false"` 以前会被 `bool("false")` 算成 `True` —— 菜单里关掉的开关重启后又开了。现在只认 `true/false`、`0/1`
- 💰 **持仓逐条校验**：`{"sh600519": "oops"}` 这种脏数据以前会一路带到绘制处 `AttributeError`。现在逐条筛，成本价必须是有穷正数，坏的那条丢掉而不是整个配置失效
- 🎆 **收盘彩蛋逐行看日期**：以前"有一行是今天"就全体放行，挂着昨天收盘价的停牌股也能跟着烧。现在只对当天的数据行触发
- 🗓 **不再有两套日历**：日期触发那个 `_is_trading_day` 只认周末，跟行情用的官方日历对不上（国庆那周会算出两种结果）。现在统一走 `market_clock`
- 🔍 **CI 拉全历史 + 覆盖 3.14**：`fetch-depth: 0`，否则"扫描全部 commit message"只看得到 1 条（扫描脚本发现只有 1 条会直接报错）；Python 3.10 / 3.13 / **3.14** 都实测
- 📦 **发过的版本不再改**：`v2.1.0` 永久指向它发布时的 commit。内容更新走新版本号，删掉了能挪 tag 的脚本，新增 `tools/release_tag.py`（tag 已存在就拒绝）

### v2.1.0

**正确性加固 + 数据源模块化**

- 🆔 **股票身份用完整代码**：`sh000001`（上证指数）和 `sz000001`（平安银行）的 6 位代码都是 `000001`，以前按下标/代码配对会串股。现在身份直接来自接口返回的变量名，漏返回一只或返回顺序变了都不会错位
- ⏱ **异步结果有版本号**：换自选股后旧的行情会被丢弃；搜索结果带关键字和编号，改了词或按了 Esc 之后旧结果不会再弹回来
- 🕘 **一律北京时间**：系统时区被改过、或者在海外，也不会把实盘判成休市；补了 2026 年官方休市日表
- 🔔 **异动提醒不再重复**：只在交易时段提醒，且是边沿触发（回到安全区才重新武装），收盘后不会每 60 秒弹同一条
- 🎆 **收盘彩蛋改成窗口触发**：14:57–15:00 内第一次拿到当天行情就触发，不再只认 14:57 那一分钟
- 🧩 **双数据源**：腾讯主源 + 新浪备源，主源挂了自动降级；搜索结果只留沪深京 A 股 / 指数 / ETF
- 🧪 **测试从干净 checkout 也能跑**：不再依赖开发者机器上那份 `stocks.json`
- 🔍 **发布卫生检查**：扫私有路径 / token / 带凭据 URL，并用 AST 检查"同一个类里有没有同名方法"
- 🖱 **修右键崩溃**：Qt 6 的 `QContextMenuEvent` 只有 `pos()`，没有 `localPos()` / `position()`，以前一右键就 `AttributeError`。现在鼠标 / 右键 / 滚轮的坐标统一走一个取值函数，逐级兜底，取不到也只当点不中，不会让挂件崩掉
- 🧪 **单实例检测不再串台**：单实例靠 Windows 命名 mutex，测试改用本进程私有名 —— 一边开着挂件一边跑测试也不会互相顶掉（以前这两条只在开发者机器上红）
- 🖥 **修 Windows 控制台编码**：英文机器控制台是 cp1252，打中文直接 `UnicodeEncodeError` 崩掉，中文机器（cp936）永远复现不了。入口统一切成 UTF-8
- 📜 **启动器 `.bat` 改成 CRLF + 纯 ASCII**：cmd 遇到裸 LF 会把中文注释和后面的命令粘成一坨，报「不是内部或外部命令」
- 📦 **依赖瘦身 245 MB → 77 MB**：改装 `PySide6-Essentials`，不再拖 168 MB 的 `PySide6_Addons`（Qt3D / QtCharts / QtWebEngine 一个都用不上）

## 快速开始

### 方式一：下载即用（推荐）

1. 到 [Releases](../../releases) 页面，下载 **Source code (zip)**
2. 解压到任意目录（建议不要放 C 盘需要权限的位置）
3. 双击 `install.bat`（建 `.venv` 并按 `requirements.txt` 装依赖，**只需一次**）
4. 双击 `start.bat`

> Release 里没有额外的打包产物，只有源码压缩包；依赖装在项目自己的 `.venv` 里，不污染全局 Python。
>
> 换机器时**拷源码目录，别拷 `.venv`**：venv 里记的是本机的绝对路径和 Python 版本，
> 不是可靠的 portable runtime。到新机器上重新跑一次 `install.bat` 就好了。
>
> **升级的用户注意**：`install.bat` / `start.bat` 每次都会验 `.venv` 里的 Python 版本，
> 不只是新建的时候。早期版本允许过 Python 3.8+，如果你手上是那时候留下的 `.venv`，
> 现在会明确报「版本不受支持」并停住 —— 删掉 `.venv` 重新跑一次 `install.bat` 即可。
> （脚本不会偷偷替你删。）

### 方式二：从源码运行

```bash
# 1. 建虚拟环境并装依赖（只装一个 PySide6）
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/

# 2. 复制示例配置
cp stocks.example.json stocks.json

# 3. 启动
.venv\Scripts\pythonw.exe widget.py
```

> 也可以直接双击 `install.bat` 单独装依赖。

### 环境要求

- Windows 10 / 11（Windows 11 上效果最佳）
- Python 3.10 – 3.14（只依赖 `PySide6-Essentials==6.11.2`，约 77 MB）
- 装的是 Essentials 而不是完整 `PySide6`：挂件只用 QtCore / QtGui / QtWidgets，完整包会多拖一个 168 MB 的 `PySide6_Addons`（Qt3D / QtCharts / QtWebEngine 等），一个都用不上

自选股和**持仓成本**都只存在 `stocks.json` 里，删错了很麻烦。现在挂件自己会存档：

- **自动存**：每次改动配置前，先把改动前那份复制进 `backups/`；每次启动也存一份
- **手动存**：右键 →「配置备份」→「立即备份」
- **回滚**：右键 →「配置备份」→ 挑一个时间点，点一下就回到那份配置（覆盖前会先把当前状态也存一份，随时能反悔）
- **看存档**：右键 →「配置备份」→「打开备份目录」

文件名形如 `stocks-20260918-213045.json`。只保留最近 **30** 份，更早的自动删。

### 出问题了怎么办（v1.4.10+）

挂件是 `pythonw` 启动的，**没有控制台窗口**，所以以前一旦出错就是"窗口不见了"，什么痕迹都没有。现在：

1. 出错时会弹一个系统提示框，写明日志路径
2. 日志在 `logs/crash-YYYYmmdd-HHMMSS.log`，里面是完整 traceback，留最近 10 份
3. 也可以主动看：右键 →「配置备份」→「崩溃日志（N）」直接打开日志目录

把那份 `.log` 发出来就能定位问题。

### 菜单项详解

**大盘指数**
窗口顶部一行显示上证 / 深证 / 创业板的涨跌幅，红绿着色，不占用 5 个个股名额。可关。

**异动提醒阈值**
个股涨跌幅绝对值达到阈值时，右下角弹系统通知，同时该行**呼吸高亮 10 秒**。默认 ±3%，可选 ±1 / ±2 / ±3 / ±5% 或关闭。

提醒是**边沿触发**，不是"每隔几分钟重复一次"：

- 涨跌幅**突破**阈值时提醒一次
- 之后一直待在阈值外**不再重复**（不会每 3 秒弹一条）
- 只有回落到「阈值 − 0.3%」以下才重新武装，再次突破才会再提醒（这个 0.3% 的回差是防在阈值附近抖动时反复弹）

> 早期版本写的是"同一只 5 分钟内不重复"，那套逻辑已经不在了：刷新间隔最短 1 秒，
> 光靠时间冷却挡不住重复弹窗。

**编辑股票代码**
逗号分隔，最多 5 只。三种写法都认：

```
600519          → sh600519
sh600519        → sh600519
600519.SH       → sh600519
```

**编辑持仓成本 / 盈亏**
格式 `代码=成本价[:股数]`，逗号分隔：

```
600519=1250:100    → 茅台成本 1250、持股 100 股，显示盈亏金额 +1066 (+8.5%)
000001=11.5        → 只有成本没股数，显示盈亏比例 -5.76%
```

- 没填成本的股票不显示盈亏
- 盈亏按 A 股习惯着色：**盈利红、亏损绿**
- **与当日涨跌分开算**——当天跌但持仓仍盈利，就是绿的涨跌幅配红的盈亏

**刷新间隔**
1 / 3 / 5 / 10 / 30 秒。非交易时段自动降为 60 秒一次。

**背景透明度**
0% ~ 100%。详见上方"不同透明度对比"。

**界面大小**
85% / 标准 / 115% / 130%。等比缩放。

**鼠标穿透**
窗口不再接收鼠标，适合压在游戏 / 全屏窗口上。开启后**必须靠托盘菜单关闭**（否则就点不到了）。

**开机自启**
写入注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。

## 配置

同目录 `stocks.json`，可直接手改后重启。首次使用请从 `stocks.example.json` 复制一份。

```json
{
  "title": "A股盯盘",
  "show_index": true,
  "alert_pct": 3.0,
  "effect_pct": 3.0,
  "codes": ["sh600519", "sz000001", "sz300750"],
  "positions": { "sh600519": { "cost": 1250.0, "shares": 100 } },
  "interval": 3,
  "bg_alpha": 190,
  "ui_scale": 1.0,
  "locked": false,
  "spark": true,
  "click_through": false,
  "always_on_top": true,
  "autostart": false,
  "pos": null
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 窗口左上角标题，最多 12 字 |
| `show_index` | bool | 是否显示大盘指数 |
| `alert_pct` | float | 异动提醒阈值（百分点），`0` 关闭 |
| `effect_pct` | float | 收盘彩蛋阈值（百分点）：14:57–15:00 内涨幅超 → 燃烧，跌幅超 → 结霜，持续 3 分钟；`0` 关闭 |
| `codes` | array | 自选股代码，最多 5 个 |
| `positions` | object | 持仓，`{"代码": {"cost": 成本, "shares": 股数}}`，`shares` 可省略 |
| `interval` | int | 刷新间隔（秒） |

### 运行时内存

> 108 MB 听着不小，但其中绝大部分是 PySide6 / Qt 运行时本身（导入 `PySide6.QtWidgets` 后空进程就有 ~90 MB）。本项目自己的数据结构只有几十 KB 量级。

### CPU 是单线程还是多核？

**是多线程进程，但不需要多核。** 实测（120 秒线程级采样，20 核机器）：

| 指标 | 数值 |
|---|---|
| 进程 CPU（单核 = 100% 基准）均值 | **0.73%** |
| 进程 CPU（20 核均摊）均值 | 0.036% |
| 最忙线程（主线程，负责 UI/重绘）占总 CPU | 73.5% |
| 是否有线程吃满一个核 | ❌ 没有，峰值也只有 1.04% |

进程里有 6~10 个线程（主线程 + 行情拉取 + 搜索 + Qt 内部线程），但工作线程几乎全程在等网络或定时器，CPU 消耗集中在主线程的重绘上。
**负载只有单核的 0.73%，这时候去"全员调动 20 个核"纯属浪费电** —— 真要让所有核一起转，反而会因为核间同步和唤醒开销把这点活干得更慢更费。
真出现 CPU 瓶颈时（比如某天要画几千个粒子），正确的做法是拆成多进程或用 Qt 的线程池，而不是让 20 个核空转。

v2.0.0 为此做的降频：平时心跳 500 ms（2 fps）、有动画才 50 ms（20 fps）、窗口不可见完全不画、`QColor` 带缓存复用。

## 30 分钟占用报告

> 实测，不是估的。挂件开着跑了 30 分钟，每 30 秒采一个点，共 60 个点。
> 采样脚本 `tools/usage_sampler.py`，出报告 `tools/report_usage.py`，原始数据留在 `tools/usage_report.csv` / `.json`。
> 机器：20 核（可调度 20 核），Windows。

### CPU

| 指标 | 均值 | 峰值 | 最低 |
|---|---|---|---|
| 进程 CPU（单核 = 100% 基准） | **0.164%** | 4.270% | 0.010% |
| 进程 CPU（20 核均摊） | 0.007% | 0.210% | 0.000% |
| 整机系统 CPU（所有核合计，含别的程序） | 14.795% | 197.28% | 1.59% |

30 分钟里，挂件平均只用了**单核的 0.164%**。峰值 4.27% 出现在刚启动的头 30 秒（加载 + 首屏绘制），之后一路贴着 0。
作为对比，同一时间整机的系统 CPU 均值是 14.8% —— **挂件的占用是整机的 1/90**。

### 内存

| 指标 | 起始 | 结束 | 均值 | 峰值 | 变化 |
|---|---|---|---|---|---|
| 工作集 RSS | 158.2 MB | **108.3 MB** | 118.6 MB | 158.3 MB | **−49.9 MB** |
| 提交内存 Pagefile | 70.8 MB | 71.6 MB | 71.5 MB | 71.7 MB | +0.8 MB |

- RSS 不但没涨，**还自己降了 50 MB**：启动瞬间要加载 Qt + 建窗口，之后 Python GC 把一次性对象回收掉，稳定在 108 MB 就不再动了
- 提交内存（真正占的虚拟内存）全程 71 MB 上下，纹丝不动
- **没有内存泄漏**。30 分钟都在 107.6 ~ 108.3 MB 这条线上平着走，连 1 MB 波动都没有

> 108 MB 里绝大部分是 PySide6 / Qt 运行时本身 —— 一个空的 `import PySide6.QtWidgets` 进程就是 90 MB 上下。挂件自己的数据结构只有几十 KB。

### 内核对象 / 线程（泄漏检测）

| 指标 | 起始 | 结束 | 均值 | 峰值 | 变化 | 判定 |
|---|---|---|---|---|---|---|
| 句柄数 | 1007 | 1008 | 1002.9 | 1013 | +1 | ✅ 稳定 |
| GDI 对象 | 45 | 47 | 46.9 | 47 | +2 | ✅ 稳定 |
| USER 对象 | 48 | 50 | 47.4 | 52 | +2 | ✅ 稳定 |
| 线程数 | 12 | 10 | 8.1 | 12 | −2 | ✅ 稳定 |

**GDI 对象是 Qt 桌面程序最典型的泄漏点**（画刷、画笔、字体没释放），30 分钟只 +2 且早就到顶不再涨，说明绘制路径是干净的。句柄 +1 同理。
线程数在 6~12 之间来回（搜索线程是临时开的，用完就退），均值 8.1 —— 没有线程泄漏。

### 一句话

挂件挂着跑 30 分钟：**CPU 占单核 0.16%，内存稳定 108 MB 不涨，GDI / 句柄零泄漏。** 开着睡觉完全没问题。

### v1.4.12

单实例唤醒认错窗口（真 bug）：
